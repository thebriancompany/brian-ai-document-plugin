# brian-docs

사람이 위에서 아래로 읽으며 이해하고, AI가 필요한 지식을 찾아 사용할 수 있는 문서를 만든다.
각 문서는 하나의 독자 목표에 집중하고, 같은 지식의 기준은 한 곳에서 관리한다.

## 작업 시작

1. 독자와 목표를 파악한다. 이 문서가 답할 질문을 한 문장으로 정한다.
2. 기존 문서와 관련 용어를 찾아 내용이 이미 있는지 확인한다.
3. 기존 내용 수정, 짧은 설명과 참조, 새 문서 작성 중 적절한 방법을 선택한다.
4. 요청한 범위와 직접 영향을 받는 문서에 변경을 적용한다.

문서가 이미 있으면 목적과 구조를 존중한다. 문장 교정 요청을 전체 문서 재구성으로 확대하지 않는다.
자료가 부족하면 확인된 내용부터 작성하고, 정확성에 필요한 정보만 질문한다.

## 필요한 지침 선택

- 작성·문장 교정·섹션 편집: [글쓰기 지침](references/writing.md)을 읽는다.
- 문서 배치·공통 내용 추출·분리·통합: [구조 지침](references/structure.md)을 읽는다.
- 문서 검토: 요청한 검토 범위에 해당하는 지침을 읽는다.

복합 작업이면 두 지침을 함께 사용한다. 선택한 지침의 예시와 구조는 상황에 맞춰 적용한다.

## 문서 유형 선택

독자가 얻으려는 결과에 맞춰 중심 유형을 정한다.

- 학습: 처음부터 따라 하며 하나의 결과를 얻는다.
- 문제 해결: 특정 작업을 수행하거나 오류를 해결한다.
- 참조: 정의, 규칙, 옵션, 동작을 정확하게 확인한다.
- 설명: 개념의 원리와 선택의 이유를 이해한다.

목표 달성에 필요한 짧은 설명과 예시는 같은 문서에 둔다.
유형을 맞추기 위해 빈 섹션을 만들거나, 완결된 흐름을 잘게 나누지 않는다.

## 변경 방식

### 작성·수정

새 내용을 넣기 전에 기존 설명을 고치거나 대체할 수 있는지 판단한다.
추가 문단은 독자가 이해하거나 행동하는 데 필요한 정보를 제공해야 한다.
사실, 적용 조건, 예시는 제공된 자료와 확인 가능한 근거에 맞춘다.

### 검토

문제 위치, 독자에게 생기는 어려움, 필요한 수정안을 짧게 제시한다.
반복 설명, 불분명한 조건, 여러 목표가 섞인 섹션 등 실제 문제를 우선한다.
취향에 따른 표현 교체를 필수 수정으로 제시하지 않는다.

### 분리·통합

옮길 내용의 기준 문서와 남길 설명을 먼저 정한다.
기존 링크와 필수 맥락을 유지하고, 달라지는 참조를 함께 고친다.
판단에 필요한 정보가 사라지지 않도록 내용의 의미와 적용 범위를 보존한다.

### 전체 구조 점검

전체 점검을 요청받았을 때 문서 간 중복, 책임 혼합, 내용상 의존 관계를 살핀다.
같은 정책을 여러 곳에서 고치게 하는 문제처럼 유지보수에 영향을 주는 항목부터 정리한다.
개선 근거가 없는 문서는 그대로 둔다.

## 마무리

변경한 내용에서 다음 사항만 확인한다.

- 독자가 필요한 답과 실행 조건을 찾을 수 있는가?
- 내용을 줄이거나 옮기면서 의미, 예외, 필수 단계가 사라지지 않았는가?
- 기준 내용이나 위치를 바꿨다면 관련 문서와 링크에 반영했는가?

원고를 요청받으면 완성된 원고를 제공한다.
파일을 수정했다면 주요 변경과 남은 확인 사항을 짧게 알린다.
