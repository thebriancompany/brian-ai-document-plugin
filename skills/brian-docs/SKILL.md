# brian-docs

사람이 위에서 아래로 읽으며 이해하고, AI가 필요한 지식을 찾아 사용할 수 있는 문서를 만든다.
각 문서는 하나의 독자 목표에 집중한다.

## 작업 범위

독자와 목표를 파악하고, 이 문서가 답할 질문을 한 문장으로 정한다.
기존 목적과 구조를 존중하며, 요청한 범위와 직접 영향을 받는 문서만 수정한다.

문장 교정은 해당 문맥을 중심으로 처리한다.

확인된 사실과 제안·가정을 구분한다.
자료가 부족하면 근거가 있는 내용부터 작성하고, 정확성에 필요한 정보만 질문한다.

## 지침의 책임과 선택

이 파일은 작업 범위, 지침 선택, 검토와 완료 기준을 관리한다.

- [글쓰기 지침](references/writing.md)은 문서 유형과 문장·섹션의 표현을 정의한다. 작성·교정할 때 읽는다.
- [구조 지침](references/structure.md)은 기준 위치, 배치, 참조와 변경 순서를 정의한다. 내용을 추가하거나 구조·규칙을 바꿀 때 읽는다.
- [계획과 이력 지침](references/planning-and-history.md)은 계획·기록의 상태와 버전·시점별 보존 방식을 정의한다. 해당 문서를 다룰 때 읽는다.

이 스킬을 수정할 때도 위 책임에 따라 기준 내용을 배치한다.
검토에는 해당 범위의 지침을 적용하고, 복합 작업이면 필요한 지침을 함께 읽는다.
예시와 권장 구조는 기존 문서와 독자의 목표에 맞춰 적용한다.

## 검토와 정리

문제 위치, 독자에게 생기는 어려움, 필요한 수정안을 짧게 제시한다.
반복 설명, 불분명한 조건, 여러 목표가 섞인 섹션 등 실제 문제를 우선한다.
취향에 따른 표현 교체를 필수 수정으로 제시하지 않고, 개선 근거가 없으면 그대로 둔다.

전체 점검을 요청받았을 때 문서 간 중복, 책임 혼합, 내용상 의존 관계를 살핀다.
같은 정책을 여러 곳에서 고치게 하는 문제처럼 유지보수에 영향을 주는 항목부터 정리한다.

## 마무리

변경한 내용에서 다음 사항만 확인한다.

- 독자가 필요한 답과 실행 조건을 찾을 수 있는가?
- 내용을 줄이거나 옮기면서 의미, 예외, 필수 단계가 사라지지 않았는가?
- 기준 내용이나 위치를 바꿨다면 관련 문서와 링크의 적용 범위를 유지했는가?

원고를 요청받으면 완성된 원고를 제공한다.
파일을 수정했다면 주요 변경과 남은 확인 사항을 짧게 알린다.
