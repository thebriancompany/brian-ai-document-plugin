# 글쓰기 지침

## 핵심부터 전달하기

제목에는 독자가 찾을 대상이나 수행할 작업을 쓴다.
첫 문단에는 핵심 답변 또는 문서를 읽고 얻을 결과를 담는다.
배경과 상세 원리는 해당 작업을 이해하는 데 필요한 위치에 둔다.

적용 대상, 버전, 조건에 따라 답이 달라지면 해당 설명 가까이에 조건을 적는다.
확인되지 않은 내용을 일반적인 사실처럼 쓰지 않는다.

## 섹션 나누기

각 섹션은 하나의 질문이나 단계에 답하도록 구성한다.
주제, 독자의 행동, 적용 조건이 달라지는 지점에서 섹션을 나눈다.

- 제목만 읽어도 문서 흐름을 이해할 수 있게 쓴다.
- 같은 수준의 제목은 비슷한 범위와 표현으로 맞춘다.
- 본문은 보통 H2와 H3로 구성한다. 더 깊어지면 내용의 배치를 다시 살핀다.
- 짧고 이어지는 설명은 한 섹션에 둔다. 문단마다 제목을 붙이지 않는다.

제목은 `기타`, `참고 사항`보다 `세션이 만료된 경우`처럼 내용을 드러내는 표현을 쓴다.
독립된 독자 목표가 생기면 문서 분리를 검토한다.

## 문장과 문단 줄이기

한 문장에는 하나의 핵심 판단이나 행동을 담는다.
조건, 이유, 예외가 한 문장에 겹치면 문장을 나누거나 목록으로 옮긴다.
연결어로 설명을 계속 이어 붙이거나 괄호 안에 긴 설명을 넣지 않는다.

한 문단은 하나의 논점을 다룬다. 짧은 문장 두세 개로 시작하고 내용에 맞춰 조정한다.
문장을 나눌 때 적용 조건과 대상이 무엇인지 유지한다.
짧게 쓰기 위해 의미 있는 조건을 삭제하거나, 뜻을 알기 어려운 명사만 나열하지 않는다.

## 위에서 아래로 읽게 구성하기

여러 항목을 문장 안에 나열해야 한다면 목록으로 풀어 쓴다.

- 순서가 없는 조건, 선택지, 특징에는 bullet을 사용한다.
- 순서가 있는 절차와 우선순위에는 숫자를 사용한다.
- 각 항목은 하나의 요점이나 행동으로 시작한다.
- 한 항목의 조건과 예외는 바로 아래에 짧게 붙인다.
- 하위 목록은 상위 항목을 구체화할 때 사용한다. 기본은 두 단계 이내로 유지한다.

목록의 깊이가 늘어나면 작은 섹션으로 나눌 수 있는지 살핀다.
이어지는 짧은 설명은 문단으로 쓰고, 각각 확인하거나 수행할 내용은 목록으로 쓴다.
문서 전체를 문장 조각으로 바꾸거나 읽는 흐름과 무관한 번호를 붙이지 않는다.

표는 같은 속성을 나란히 비교해야 할 때 사용한다.
셀에 긴 문장이 쌓이거나 가로로 넓어지면 항목별 소제목과 목록으로 바꾼다.
문장의 시각적 길이를 줄이기 위한 강제 줄바꿈보다 문장 구조를 먼저 다듬는다.

## 불필요한 설명 덜기

독자의 이해, 판단, 실행에 도움이 되는 내용을 남긴다.

- 내용을 예고하기만 하는 도입과 같은 말을 반복하는 결론은 덜어낸다.
- 당연한 설명, 의미 없는 강조, 주제에서 벗어난 배경은 줄인다.
- 예시는 이해를 돕는 대표 사례부터 제시한다. 같은 설명의 변형을 늘리지 않는다.
- FAQ, 주의사항, 요약은 실제로 필요한 내용이 있을 때만 둔다.

전제 조건, 중요한 예외, 실패 시 필요한 조치는 해당 단계 가까이에 유지한다.
문장을 줄여도 독자가 수행할 작업은 완결되어야 한다.

## 일부만 읽어도 이해하게 쓰기

같은 개념에는 같은 용어를 사용한다. 약어는 독자에게 필요하면 처음 등장할 때 풀어 쓴다.
문단의 대상이 모호해지면 `이것`, `위 내용` 대신 실제 이름을 쓴다.
링크에는 연결 대상의 주제나 작업을 적는다.
현재 문단을 이해할 짧은 맥락을 제공하고, 상세 정의는 기준 문서로 연결한다.

단계별로 정리한 문장:

> 관리자 권한으로 로그인한 뒤 알림을 설정하세요.
>
> 1. 설정 화면에서 알림을 켜세요.
> 2. 수신 주소를 입력하고 저장하세요.
> 3. 테스트 알림을 보내 수신 여부를 확인하세요.
