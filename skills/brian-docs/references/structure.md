# 구조 지침

## 책임 정하기

문서마다 독자가 해결할 핵심 질문을 정한다.
같은 목표를 위해 읽고 같은 이유로 바뀌는 내용은 함께 둔다.
독자, 목적, 변경 이유가 달라지면 별도 문서로 나눌 수 있는지 살핀다.

하나의 작업에 필요한 준비, 실행, 결과 확인은 함께 읽을 수 있게 유지한다.
한 문서의 길이만으로 분리 여부를 결정하지 않는다.

## 기준 문서 정하기

정의, 정책, 규칙, 공통 절차는 각각 관리할 기준 위치를 정한다.
내용의 책임이 있는 도메인에 두고, 다른 문서는 필요한 부분을 참조한다.

- 기존 기준 문서가 있으면 그 내용을 먼저 수정한다.
- 상세 규칙을 다른 문서에 복제하기보다 짧은 설명과 링크를 제공한다.
- 변경 가능한 수치와 조건을 다시 적어야 한다면 기준 문서와 연결하고 변경 시 함께 확인한다.
- 코드나 스키마에서 결정되는 정보는 해당 근거를 연결한다.
- 기록과 현재 동작이 다르면 차이를 드러내고 적용 기준을 확인한다.

독자의 현재 작업에 필요한 짧은 요약과 예시는 각 문서에 둘 수 있다.
겉보기 표현이 비슷해도 적용 조건이나 책임이 다르면 무리하게 합치지 않는다.
하나의 사용처만 있는 내용을 예상 재사용만으로 공통 문서로 추출하지 않는다.

## 폴더 배치

기존 저장소의 구조를 우선한다. 새 구조가 필요하면 도메인을 먼저 나누고 필요한 문서 유형을 배치한다.

```text
docs/
├── index.md                    # 시작점과 문서 지도
├── shared/                     # 도메인에 종속되지 않는 공통 정의
├── domains/
│   └── auth/
│       ├── reference/          # 정책과 규칙
│       ├── explanations/       # 원리와 배경
│       └── guides/             # 작업 방법
└── journeys/                   # 여러 도메인을 연결하는 절차
```

필요한 폴더만 만든다. 작은 문서 집합은 더 평평한 구조로 시작해도 된다.
도메인의 지식은 다른 도메인에서도 사용한다는 이유만으로 `shared`로 옮기지 않는다.
문서 지도에는 읽을 순서와 짧은 소개를 두고 각 문서의 내용을 다시 작성하지 않는다.

## 의존 방향

내용상 의존은 기준 내용이 바뀌면 참조하는 문서도 검토해야 하는 관계다.
기본 방향은 통합 절차 → 도메인 지식 → 공통 정의로 둔다.
도메인 사이에서는 상대 도메인의 기준 문서를 참조한다.

- 기준 정의가 특정 사용 사례의 설명을 전제로 삼지 않도록 한다.
- 서로를 전제로 해야만 이해할 수 있다면 공통 전제를 추출하거나 관련 내용을 합친다.
- 실제로 함께 바뀌는 내용은 책임과 배치를 다시 살핀다.

다음 읽을거리, 상위 목차, 사례 소개는 탐색 링크다. 양방향으로 연결할 수 있다.
일반 링크를 모두 내용상 의존으로 취급하지 않는다.
관계는 설명이 있는 링크로 표현한다. 기존 관리 방식이 없다면 별도 메타데이터나 수동 관계 목록을 요구하지 않는다.

## 분리·통합 판단

아래 상황이 생기면 문서를 나눌 수 있는지 살핀다.

- 서로 다른 독자 목표가 섞여 있다.
- 별도로 수정되고 재사용되는 정의나 정책이 묻혀 있다.
- 예외와 부가 설명이 핵심 절차를 가린다.

아래 상황에서는 합치거나 필요한 맥락을 되돌린다.

- 짧은 문서를 연달아 열어야 하나의 절차를 수행할 수 있다.
- 문서들이 항상 같은 이유로 바뀌고 책임도 겹친다.
- 분리한 문서가 원래 문서 없이는 의미를 전달하지 못한다.

분리한 뒤 원래 문서에는 필요한 요약과 연결을 남긴다.
길이를 줄이기 위해 상세 내용을 부록이나 다른 파일에 그대로 쌓아두지 않는다.
문서 수, 내용 중복, 독자의 이동 부담을 함께 고려한다.

## 변경의 영향 처리

기준 내용을 바꾸면 이를 사용하는 문서와 예시를 찾아 필요한 부분만 갱신한다.
이름이나 위치를 바꾸면 연결된 파일 경로와 섹션 링크도 함께 바꾼다.
직접 관련된 문서부터 읽고, 필요한 기준 내용을 따라가며 범위를 넓힌다.

과거 결정과 폐기된 절차를 현재 지침과 구분한다.
이력이 필요하면 당시 맥락과 대체 문서를 표시해 보존한다.
변경할 때마다 별도의 요약·감사·관계 문서를 새로 만들지 않는다.
