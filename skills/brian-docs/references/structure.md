# 구조 지침

## 분리·통합 판단

같은 독자 목표와 역할을 가진 내용은 함께 둔다.

- 분리: 독자 목표나 관리 책임이 다르다. 부가 설명이 핵심 절차를 가리는 경우도 검토한다.
- 통합: 하나의 절차를 위해 여러 짧은 문서를 열어야 하거나, 책임이 겹쳐 같은 이유로 함께 바뀐다.
- 유지: 준비, 실행, 결과 확인이 하나의 완결된 작업을 이룬다.

분리할 때는 옮길 내용의 기준 위치를 정하고, 원래 문서에 필요한 요약과 연결을 남긴다.
길이만 줄이려 내용을 부록이나 다른 파일로 밀어내지 않는다.
문서 수, 내용 중복, 독자의 이동 부담을 함께 고려한다.

## 기준 문서 정하기

같은 적용 범위의 정의, 정책, 규칙, 공통 절차는 한 곳에서 관리한다.
내용의 책임이 있는 도메인에 두고, 다른 문서는 필요한 부분을 참조한다.
문서의 개요와 섹션 제목에서 직접 정의할 내용과 참조할 내용을 드러낸다.
규칙에는 적용 대상·조건과 해야 할 행동을 함께 적는다.

- 재사용할 때는 상세 규칙 대신 짧은 설명·예시와 기준 문서 링크를 제공한다.
- 변경 가능한 수치와 조건을 다시 적어야 한다면 기준 문서와 연결하고 변경 시 함께 확인한다.
- 코드나 스키마에서 결정되는 정보는 해당 근거를 연결한다.
- 현재 동작을 설명하는 문서가 근거와 다르면 차이를 드러내고 적용 기준을 확인한다.

겉보기 표현이 비슷해도 적용 조건이나 책임이 다르면 무리하게 합치지 않는다.
하나의 사용처만 있는 내용을 예상 재사용만으로 공통 문서로 추출하지 않는다.

## 폴더 배치

기존 구조를 우선한다. 새 구조가 필요하면 지식은 도메인별로, 계획과 기록은 역할별로 배치한다.

```text
docs/
├── index.md                    # 시작점과 문서 지도
├── shared/                     # 도메인에 종속되지 않는 공통 정의
├── domains/
│   └── auth/
│       ├── reference/          # 정책과 규칙
│       ├── explanations/       # 원리와 배경
│       └── guides/             # 작업 방법
├── journeys/                   # 여러 도메인을 연결하는 절차
├── roadmap.md                  # 현재 방향과 우선순위
├── plans/                      # 버전·단계별 계획
├── releases/                   # 배포된 결과
└── decisions/                  # 결정 배경과 이유
```

필요한 폴더만 만든다. 작은 문서 집합은 더 평평한 구조로 시작해도 된다.
도메인의 지식은 다른 도메인에서도 사용한다는 이유만으로 `shared`로 옮기지 않는다.
문서 지도에는 읽을 순서와 짧은 소개를 두고 각 문서의 내용을 다시 작성하지 않는다.

## 의존 방향

내용상 의존은 기준 내용이 바뀌면 참조하는 문서도 검토해야 하는 관계다.
현재 지식의 기본 방향은 통합 절차 → 도메인 지식 → 공통 정의로 둔다.
도메인 사이에서는 상대 도메인의 기준 문서를 참조한다.

- 기준 정의가 특정 사용 사례의 설명을 전제로 삼지 않도록 한다.
- 서로를 전제로 해야만 이해할 수 있다면 공통 전제를 추출하거나 관련 내용을 합친다.

다음 읽을거리, 상위 목차, 사례 소개는 탐색 링크다. 양방향으로 연결할 수 있다.
일반 링크를 모두 내용상 의존으로 취급하지 않는다.
관계는 설명이 있는 링크로 표현한다. 기존 관리 방식이 없다면 별도 메타데이터나 수동 관계 목록을 요구하지 않는다.

## 기준 내용 변경

계획이나 과거 기록을 함께 다룬다면 먼저 [계획과 이력 지침](planning-and-history.md)을 읽는다.

1. 같은 개념이나 판단을 다루는 기준 문서·섹션을 찾고, 적용 대상·버전·시점을 비교한다.
2. 같은 내용이면 기존 기준을 참조한다. 같은 범위의 변경은 원문에 반영한다. 다른 범위의 내용은 구분해 정의하고 연결한다.
3. 새 조건이나 예외가 생기면 일반 규칙의 적용 범위도 함께 고친다. 별도 설명은 해당 조건에서 연결한다.
4. 기준이 없으면 책임에 맞는 기존 섹션에 둔다. 새 문서가 필요한지는 분리·통합 기준으로 판단한다.
5. 같은 적용 범위에서 영향을 받는 현재 문서와 예시를 갱신한다.

이름이나 위치를 바꿀 때는 링크가 원래의 버전·시점을 계속 가리키도록 수정한다.
변경한 기준과 이를 사용하는 문서를 중심으로 처리한다.
변경할 때마다 별도의 규칙 목록이나 점검 보고서를 추가하지 않는다.
