# 계획과 이력 지침

## 공통 기준

첫 부분에 문서의 역할과 필요한 상태를 표시한다.
대상 버전과 기준 시점은 내용의 해석에 필요할 때 표시한다.
기존 표기 방식을 따르고, 별도 메타데이터 양식을 강제하지 않는다.
아래 구성 항목은 필요한 것만 사용한다.

계획은 진행 상황에 맞춰 갱신하고, 확정된 결과와 채택한 결정은 당시 맥락을 보존한다.
과거 기록은 현재 설명과 문장이 같다는 이유만으로 삭제하지 않는다.
과거 기록의 오류는 바로잡을 수 있다. 의미를 바꾸는 정정은 바뀐 내용과 이유를 남긴다.

과거의 근거는 해당 버전 문서나 고정된 이력으로 연결한다.
현재 기준을 안내하는 링크와 구분해, 참조 대상의 변경이 과거 기록의 의미를 바꾸지 않게 한다.

## 로드맵

현재의 방향과 우선순위를 보여준다.
필요하면 다음 구분을 사용한다.

- 진행 중: 현재 집중하는 목표
- 다음: 이어서 진행할 계획
- 후보: 아직 확정하지 않은 아이디어

각 항목에는 목표를 짧게 쓰고 상세 계획이 있으면 연결한다.
요구사항과 작업 목록은 상세 계획에서 관리한다.
일정은 확정일과 예상 시점을 구분한다. 근거가 없으면 미정으로 둔다.

완료·중단한 항목은 결과와 남은 내용을 보존한 뒤 활성 목록에서 정리한다.
계획이 끝났다는 이유만으로 배포가 완료되었다고 표시하지 않는다.

## 버전별 계획

한 버전이나 개발 단계에서 달성할 목표와 범위를 관리한다.

- 목표: 끝났을 때 얻을 결과
- 범위: 포함할 내용과 이번에 다루지 않을 내용
- 완료 기준: 결과를 판단할 구체적인 조건
- 상태: 초안, 진행, 완료, 보류, 중단 등 현재 상황

중요한 범위 변경은 바뀐 내용과 이유를 짧게 남긴다.
완료하거나 중단하면 실제 결과와 남은 항목을 정리하고 후속 계획이 있으면 연결한다.

다음 계획에는 새로운 목표와 달라진 범위를 쓴다.
공통 정의와 이어받는 항목은 참조하고, 이전 계획을 통째로 복제하지 않는다.
계획의 단계명과 실제 제품 버전을 혼동하지 않도록 적용 대상을 명시한다.

## 릴리스 기록

실제로 배포된 변경과 사용자에게 미치는 영향을 기록한다.
기존 버전 표기를 따르고, 확인된 배포일과 대상 버전을 적는다.
배포가 확인되지 않았다면 초안임을 표시한다.

- 추가·변경·제거된 기능
- 사용자에게 미치는 영향
- 필요한 전환 작업
- 해당 버전에 적용되는 문서 링크

계획 목록을 그대로 옮기지 않고 확인된 결과만 반영한다.
이후 버전의 동작은 새 릴리스 기록에서 설명한다.

## 결정 기록

중요한 선택의 배경과 근거를 보존한다.

- 해결하려던 문제
- 선택한 방법과 이유
- 감수한 제약과 영향
- 제안, 채택, 대체 등 결정의 상태

제안 중인 결정은 수정할 수 있다.
채택한 판단을 바꾸면 새 결정에서 변경 이유를 설명한다.
이전 기록에는 대체 상태와 후속 결정 링크를 남긴다.

현재 규칙은 기준 문서에서 관리한다. 결정 기록에는 판단에 필요한 당시 내용을 남긴다.

## 기록 나누기

작은 수정은 기존 변경 이력으로 관리한다.
새 버전, 릴리스, 중요한 결정처럼 구분할 이유가 있을 때 기록을 나눈다.
과거 원문을 별도로 보존해야 할 때만 기준 시점을 표시한 사본을 만든다.
폴더를 새로 배치하거나 참조 관계를 바꿀 때는 [구조 지침](structure.md)을 따른다.

## 버전별 사용 설명서

여러 제품 버전의 사용법을 동시에 제공해야 할 때 버전별 문서를 유지한다.
계획이 여러 단계라는 이유만으로 사용 설명서 전체를 버전별로 복제하지 않는다.

동일하게 적용되는 내용은 대상 버전을 표시해 공유한다.
변경이 일부 버전에만 해당하면 내용을 분리해 다른 버전의 설명을 보존한다.
